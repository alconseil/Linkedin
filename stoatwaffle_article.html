TL;DR

StoatWaffle is a modular Node.js malware (Stealer + RAT) deployed by WaterPlum Team 8 — a North Korean threat actor. It weaponizes a native VS Code feature (.vscode/tasks.json with runOn: folderOpen) to achieve zero-click compromise the instant a developer opens a malicious blockchain-themed repository. This is a decisive evolution of the Contagious Interview campaign, active since 2022.

01

Contagious Interview — The Industrial Campaign

Since at least 2022, WaterPlum (also tracked as DeceptiveDevelopment, DEV#POPPER, TAG-121, PurpleBravo) has operated the most prolific developer-targeting campaign ever documented. Their playbook is precise: fake recruiter profiles, bogus coding assignments, malicious packages — and now, weaponized IDE configurations.

⚠ Critical Context

The FBI seized the BlockNovas front company domain (April 2025) — a fake tech firm with AI-generated employee profiles used to deliver malicious coding tests. WaterPlum immediately rebuilt equivalent infrastructure and continued operations without interruption.

Infrastructure Evolution (2022 → 2026)

2022–2023 Genesis

Fake recruiter profiles on LinkedIn and job boards. Developers invited to "technical interviews" and asked to clone/run projects containing BeaverTail infostealer and InvisibleFerret backdoor.

2024 npm at scale

Industrial npm poisoning. OtterCookie introduced — merges BeaverTail with a remote shell. GitLab bans 131 accounts. 338+ malicious packages deployed in a single wave. Vercel used as staging layer.

Late 2024 Anti-Analysis

Payload staging split across GitHub + Vercel + C2. Anti-sandbox detection in OtterCookie. Invite-only private repos. Staging URLs return decoy content unless correct HTTP headers are supplied — defeating automated scanners.

Dec 2025 → 2026 StoatWaffle

Team 8 abandons OtterCookie for StoatWaffle. Zero-click compromise via VS Code workspace tasks. Node.js Stealer + RAT deployed within minutes. WSL-aware. Keychain-targeting on macOS. IDE is now the entry point.

ℹ Attribution

ESET Research documented direct code links between DeceptiveDevelopment's Tropidoor backdoor and the PostNapTea RAT used by the Lazarus group, confirming WaterPlum's integration into North Korea's broader cyber offensive apparatus. MITRE tracks this as G1052.

Attack Flow — Zero-Click Compromise

StoatWaffle's key innovation is eliminating the final friction point of all prior Contagious Interview variants: manual script execution. The entire kill chain fires from a single developer action — opening a folder.

⚡ Key Innovation

VS Code's native tasks.json with runOn: folderOpen fires automatically when a workspace is opened and marked as trusted. No click, no install, no warning after the initial trust prompt — which most developers dismiss reflexively.

Step 1 — Lure Delivery Social Engineering

Developer receives a blockchain/Web3 repository via LinkedIn, job board, or direct message — framed as a "coding test" or "open source contribution". Repository has a realistic README, proper commit history, and plausible project structure.

Step 2 — Folder Trust VS Code Abuse

Developer opens the folder in VS Code and clicks "Yes, I trust the authors". The .vscode/tasks.json task fires immediately, downloading an initial payload from a Vercel-hosted endpoint via cmd.exe. Terminal: hidden (reveal: "never").

Step 3 — Bootstrap Environment Prep

vscode-bootstrap.cmd checks for Node.js. If absent, downloads and installs it from the official site (bypassing LOLBin heuristics). Downloads env.npl + package.json, executes env.npl via Node.js.

Step 4 — C2 Polling Staged C2

env.npl polls /api/errorMessage every 5 seconds. Error-status responses are executed as live Node.js code. ~5 min later: second downloader delivered, polling /api/handleErrors.

Step 5 — Module Deployment Full Compromise

Both Stealer and RAT modules deployed simultaneously. Credential harvesting begins. Persistent C2 shell established. The attacker has complete interactive access to the developer workstation and all secrets it holds.

03

Stealer Module — Targeted Credential Harvesting

The Stealer adapts its behavior to the victim's OS and browser. Files are copied under a random name to a temporary directory, then exfiltrated to /upload on the C2. A software inventory goes separately to /uploadsecond.

► Chromium (Chrome, Edge, Brave, Opera)

Harvests Login Data (SQLite credential store) AND Local Extension Settings — directly targeting crypto wallet extensions: MetaMask, Phantom, Coinbase Wallet, Exodus, etc.

► Firefox

Reads extensions.json to enumerate installed extensions, checks for designated wallet keywords. Harvests key4.db and logins.json for all stored credentials.

► macOS — Keychain

Additionally exfiltrates login.keychain-db — Apple's native credential store containing Wi-Fi passwords, application tokens, certificates, and SSH keys.

🔬 Advanced: WSL Boundary Crossing

The Stealer detects WSL execution contexts. If running inside WSL, it retrieves the Windows user profile path and converts it via wslpath, allowing Node.js on WSL to access and exfiltrate Windows filesystem data. A cross-boundary pivot rarely seen in commodity malware — demonstrating deep familiarity with developer environments.

04

RAT Module — Persistent Interactive Control

The RAT polls /api/hsocketNext for commands, returns results to /api/hsocketResult. Entirely Node.js — no compiled binary, cross-platform, minimal disk footprint.

CommandActionSeverity
exitTerminate RAT processMedium
cd [dir]Change working directoryMedium
ls / dirList files and directoriesMedium
get [file]Download arbitrary file to C2High
eval [code]Execute arbitrary Node.js code in-processCritical
shell [cmd]Execute arbitrary shell commandCritical
appNavigate to application directoryInfo
detailRetrieve detailed directory infoMedium
🔴 Highest Risk: eval

The eval command executes Node.js in-process — no child process spawn, no EDR spawn event, no process tree anomaly. Combined with shell, the attacker has full OS execution while remaining largely invisible to traditional process-based detection.

06

Microsoft Sentinel — Detection Rules

ℹ Prerequisites

Requires: Microsoft Defender for Endpoint tables (DeviceProcessEvents, DeviceNetworkEvents, DeviceFileEvents) connected to Sentinel, and Security Events with Event ID 4688 command-line auditing enabled.

Rule 1 — VS Code Spawning Node.js

KQL · Scheduled Rule · Severity: High
// node.exe spawned by Code.exe — StoatWaffle Step 3 signature
DeviceProcessEvents
| where TimeGenerated > ago(1d)
| where InitiatingProcessFileName =~ "Code.exe"
    and FileName =~ "node.exe"
| where ProcessCommandLine has_any("env.npl", "vscode-bootstrap",
    "errorMessage", "handleErrors")
| project TimeGenerated, DeviceName, AccountName,
    InitiatingProcessFileName, FileName, ProcessCommandLine
| extend RiskScore = 80,
    Technique = "T1204.002 - User Execution: Malicious File"

Rule 2 — C2 Beaconing (5-second interval)

KQL · Scheduled Rule · Severity: Critical
// Detects StoatWaffle's characteristic 5s C2 polling from node.exe
DeviceNetworkEvents
| where TimeGenerated > ago(1d)
| where InitiatingProcessFileName =~ "node.exe"
| where RemoteUrl has_any("/api/errorMessage", "/api/handleErrors",
    "/api/hsocketNext", "/api/hsocketResult",
    "/upload", "/uploadsecond")
| summarize CallCount = count(),
    FirstSeen = min(TimeGenerated), LastSeen = max(TimeGenerated)
    by DeviceName, RemoteIP, RemoteUrl, InitiatingProcessFileName
| where CallCount > 10
| extend IntervalSeconds =
    datetime_diff('second', LastSeen, FirstSeen) / toreal(CallCount)
| where IntervalSeconds between (3 .. 8)   // ~5s window
| extend RiskScore = 95,
    Technique = "T1071.001 - C2 Application Layer Protocol"

Rule 3 — Known C2 IOC Match

KQL · IOC Match · Severity: High
let StoatWaffleC2 = dynamic([
    "185.163.125.196", "147.124.202.208",
    "163.245.194.216", "66.235.168.136", "87.236.177.9"

union DeviceNetworkEvents, CommonSecurityLog
| where DestinationIP in (StoatWaffleC2)
    or SourceIP in (StoatWaffleC2)
    or RemoteIP in (StoatWaffleC2)
| extend ThreatFamily = "StoatWaffle",
    ThreatActor = "WaterPlum / DPRK",
    Technique = "T1071.001"
| project TimeGenerated, DeviceName, SourceIP,
    DestinationIP, RemotePort, InitiatingProcessFileName,
    ThreatFamily, ThreatActor

Rule 4 — Browser Credential DB Access by Node.js

KQL · Scheduled Rule · Severity: Critical
// StoatWaffle Stealer — browser credential store access
DeviceFileEvents
| where TimeGenerated > ago(1d)
| where InitiatingProcessFileName =~ "node.exe"
| where FolderPath has_any(
    "\\Google\\Chrome\\User Data\\Default\\Login Data",
    "\\Microsoft\\Edge\\User Data\\Default\\Login Data",
    "\\Mozilla\\Firefox\\Profiles",
    "key4.db", "logins.json",
    "extensions.json", "Local Extension Settings"
  )
| project TimeGenerated, DeviceName,
    InitiatingProcessAccountName, FolderPath, FileName, ActionType
| extend RiskScore = 90,
    Technique = "T1555.003 - Credentials from Web Browsers"

Rule 5 — WSL Path Conversion Abuse

KQL · Scheduled Rule · Severity: High
// node.exe invoking wslpath — WSL boundary-crossing pivot
DeviceProcessEvents
| where TimeGenerated > ago(1d)
| where InitiatingProcessFileName =~ "node.exe"
| where FileName =~ "wslpath"
    or (FileName =~ "wsl.exe" and ProcessCommandLine has "wslpath")
| extend RiskScore = 85,
    Technique = "T1202 - Indirect Command Execution"

Rule 6 — Vercel Payload Staging

KQL · Hunting Query · Severity: Medium
// High-frequency Vercel calls from dev tooling — staging pattern
DeviceNetworkEvents
| where RemoteUrl has "vercel.app"
| where InitiatingProcessFileName has_any(
    "node.exe", "cmd.exe", "Code.exe")
| summarize count() by DeviceName, RemoteUrl,
    InitiatingProcessFileName, bin(TimeGenerated, 1h)
| where count_ > 5

⭐ Composite Rule — Multi-Signal High-Fidelity

✓ Recommended — Highest Signal-to-Noise

Correlates three independent signals on the same device within 1 hour. Very low false-positive rate. Deploy as a Scheduled Analytic Rule with Critical severity + automated SOAR playbook.

KQL · Composite Rule · Severity: Critical
// Multi-signal: VSCode spawn + credential access + C2 beacon (same device, 1h)
let vscode_spawn = DeviceProcessEvents
    | where TimeGenerated > ago(24h)
    | where InitiatingProcessFileName =~ "Code.exe"
        and FileName =~ "node.exe"
    | project DeviceName, T_spawn = TimeGenerated;

let cred_access = DeviceFileEvents
    | where TimeGenerated > ago(24h)
    | where InitiatingProcessFileName =~ "node.exe"
    | where FolderPath has_any("Login Data", "key4.db",
        "extensions.json", "Local Extension Settings")
    | project DeviceName, T_cred = TimeGenerated;

let c2_beacon = DeviceNetworkEvents
    | where TimeGenerated > ago(24h)
    | where InitiatingProcessFileName =~ "node.exe"
    | where RemoteUrl has_any("/api/errorMessage",
        "/api/hsocketNext", "/upload")
    | project DeviceName, T_c2 = TimeGenerated;

vscode_spawn
| join kind=inner cred_access on DeviceName
| join kind=inner c2_beacon   on DeviceName
| where abs(datetime_diff('minute', T_spawn, T_cred)) < 60
    and abs(datetime_diff('minute', T_spawn, T_c2))  < 60
| distinct DeviceName, T_spawn, T_cred, T_c2
| extend AlertName  = "StoatWaffle — Composite Detection",
    Severity   = "Critical",
    Tactics    = "Execution | Credential Access | C2",
    Techniques = "T1204.002 | T1555.003 | T1071.001"

09

Conclusion

StoatWaffle is not an isolated malware family — it is the latest chapter in a state-sponsored, industrialised campaign that has evolved consistently since 2022, each iteration more evasive, more automated, and more deeply embedded in the developer's trusted toolchain.

🔴 Paradigm Shift

The attack surface has moved. Monitoring production pipelines and package registries is no longer sufficient. The developer workstation and IDE are now primary attack vectors — and the trust model developers extend to their own tools is being weaponized at scale by a well-funded nation-state actor.

A compromised developer workstation is not a dead end. It is an entry point into cloud infrastructure, CI/CD pipelines, secrets managers, and production systems. The density of high-value credentials on a developer machine — tokens, private keys, certificates, database connections — makes it one of the most valuable initial access targets in any enterprise.

🟣 For Enterprise Security Teams

Extend detection scope to developer environments: VS Code telemetry, Node.js process lineage, WSL boundary crossings, IDE workspace configurations. The composite Sentinel rule in §06 gives you immediate detection coverage with minimal false positives. Start there. Deploy today.

The question is no longer "will developers be targeted?" — they are, at industrial scale. The question is: do you have the visibility to know when it happens?
